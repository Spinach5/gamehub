# 多语言（i18n）设计规格

- 日期：2026-10-28
- 状态：已确认（跟随系统默认、翻译界面 + 应用层错误、外观卡片内下拉、内建 JSON 方案）
- 范围：`crates/ui`（含新增语言目录与 `docs/i18n.md`）、`crates/application`（仅新增设置键常量）
- 非范围：`launch` / `prefix` / `runner-wine` / `storage` 的底层技术报错文案

## 1. 背景

当前全部界面文案以中文字面量散落在 `crates/ui/src` 中：约 304 处中文字面量、221 条
唯一文案；`application::AppError` 另有 19 条面向用户的错误；`DraftError` 约 15 条表单
校验文案；设置解析错误约 8 条。没有任何 i18n 基础设施。

本次引入内建 i18n 模块，提供简体中文与 English 两种语言，可在设置中切换；目标是把
「新增一种语言」的成本压到**新增一个 JSON 文件 + 注册表加一行**，并用手工可跑的测试
防止漏译和 key 漂移。

## 2. 目标与非目标

### 目标

1. 界面语言可在设置页「外观」卡片内切换，立即生效、立即持久化，无需重启。
2. 默认「跟随系统」：按 `LANGUAGE → LC_ALL → LC_MESSAGES → LANG` 探测；`zh*` 显示
   简体中文，其余显示 English。
3. 新增语言只改数据：`crates/ui/locales/<code>.json` + `LANGUAGES` 注册表一行。
4. 翻译范围覆盖：全部界面文案、下拉选项、文件对话框标题、启动状态、表单校验错误、
   设置读写错误、`AppError` 的用户可见部分。
5. 测试锁定：各语言 key 集合一致、占位符一致、源码中使用的 key 都存在。

### 非目标

- 不翻译 Wine / gamescope / 日志正文，不翻译 `launch` / `prefix` / `storage` 等底层
  技术错误（它们只作为 detail 原样展示，便于检索）。
- 不做运行时跟随系统语言变化（修改系统语言后需重启应用）。
- 不做 RTL 布局、按语言切换字体、本地化数字/日期/货币格式。
- 不做复数规则引擎；仅区分「1 / 非 1」两种形式。
- 不翻译启动失败时 stderr 输出与窗口标题（标题固定 `gamehub`）。
- 不引入新的第三方 i18n 依赖。

## 3. 架构

### 3.1 文件布局

```
crates/ui/locales/zh-CN.json      # 简体中文目录
crates/ui/locales/en-US.json      # English 目录
crates/ui/src/i18n/mod.rs         # Language / LanguagePref / 查找 API / 探测
crates/ui/src/i18n/errors.rs      # AppError → 本地化文本
docs/i18n.md                      # 新增语言维护指南
```

语言目录通过 `include_str!` 编译进二进制，运行时不存在缺文件问题。

### 3.2 Language 注册表

```rust
pub struct Language {
    pub code: &'static str,        // BCP-47，如 "zh-CN"
    pub native_name: &'static str, // 母语名，如 "简体中文"
    catalogue: &'static str,       // include_str!("../../locales/zh-CN.json")
}

pub const ZH_CN: Language = /* code "zh-CN" */;
pub const EN_US: Language = /* code "en-US" */;
pub const LANGUAGES: &[Language] = &[ZH_CN, EN_US];
pub const FALLBACK: Lang = &EN_US;
pub type Lang = &'static Language;
```

- `Language` 的 `PartialEq` / `Eq` 只比较 `code`。
- 顺序即设置页下拉顺序；第一个不代表默认语言（默认由 `LanguagePref::Auto` 决定）。
- 下拉展示 `native_name`，让看不懂当前语言的用户也能找到自己的语言。

### 3.3 设置值与解析

新增设置键 `ui_language`：在 `crates/application/src/settings.rs` 增加
`SETTING_UI_LANGUAGE = "ui_language"`，与 `SETTING_UI_THEME` 一并从 `application` 导出。

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub enum LanguagePref {
    #[default]
    Auto,
    Fixed(Lang),
}
```

- 存储值：`"auto"` 或语言 code（如 `"zh-CN"`）。
- `from_setting(Option<&str>)`：缺失、空串、未知 code 一律回退 `Auto`。
- `resolve()`：`Auto` 调 `detect_system_language()`，`Fixed` 直接返回。
- 系统探测按 `LANGUAGE`（冒号分隔列表，逐个匹配）→ `LC_ALL` → `LC_MESSAGES` →
  `LANG` 的顺序，取第一个可识别的 tag；全部无法识别时回退 `FALLBACK`。
- tag 归一化：去掉 `.` 与 `@` 之后的部分，`_` 视为 `-`，大小写不敏感；先精确匹配
  code，再按主语言子标签匹配（`zh` → `zh-CN`，`en` → `en-US`）。
- `C` / `POSIX` / 空值视为不可识别。

### 3.4 查找 API

```rust
pub fn tr(lang: Lang, key: &'static str) -> &'static str;
pub fn tr_args(lang: Lang, key: &'static str, args: &[(&str, &str)]) -> String;
pub fn tr_plural(lang: Lang, one: &'static str, other: &'static str, n: u64) -> &'static str;
pub fn tr_plural_args(
    lang: Lang,
    one: &'static str,
    other: &'static str,
    n: u64,
    args: &[(&str, &str)],
) -> String;
```

- 回退链：所选语言 → `FALLBACK`（en-US）→ key 本身。
- 占位符写作 `{name}`，`tr_args` 逐项替换；未提供的占位符原样保留（测试保证不出现）。
- 目录首次访问时解析成 `HashMap<String, String>` 并泄漏为 `'static`，因此 `tr` 可返回
  `&'static str`，视图层无需处理生命周期。
- 编译期嵌入的 JSON 若解析失败：记录 `tracing::error!` 并使用空目录（回退到英文/key），
  不阻断启动；测试会直接暴露此类错误。
- 复数采用双 key 约定（`*.one` / `*.other`），`n == 1` 选前者。中文两条文案可以相同。
  以后若加入俄语等多形式语言，再扩展为复数形式表；本规格不实现。

### 3.5 key 命名规范

扁平点分命名，按界面/职责分区：

| 前缀 | 内容 |
| --- | --- |
| `common.*` | 保存、取消、删除、添加、选择、清除、返回、刷新、关闭、未选择、未知、自动 |
| `nav.*` | 游戏库、Runner 管理、日志、设置 |
| `library.*` | 游戏库标题、副标题、空状态、全部游戏 |
| `launch.*` | 启动中、游玩、结束中、异常退出 |
| `detail.*` | 游戏详情所有字段、卡片、提示、确认删除 |
| `runners.*` | Runner 管理页、徽章、提示 |
| `logs.*` | 日志页 |
| `settings.*` | 设置页、外观、语言、兼容层增强、全局环境变量 |
| `draft.*` | 表单字段名与校验消息 |
| `choices.*` | 架构、显示后端、gamescope、DLL override、显示器、Runner 默认项 |
| `dialogs.*` | 文件对话框标题与失败提示 |
| `errors.*` | `AppError` 与通用错误分类 |
| `time.*` | 「从未」「刚刚」等相对时间 |

同一文案被多处使用才放 `common.*`；有语境的文案放各自分区，避免英文词义被上下文
绑架。

## 4. 界面接入

### 4.1 设置页

「外观」卡片改为两行：

```
┌ 外观 ─────────────────────────────┐
│ 主题   [ 浅色 | 深色 ]             │
│ 语言   [ 跟随系统            ▾ ]   │
└────────────────────────────────────┘
```

- 语言行使用 `pick_list`（沿用 `styles::pick_list` / `styles::menu`），选项为
  `Choice<LanguagePref>`：第一项为本地化的「跟随系统 / Follow system」，其余为各语言
  `native_name`。
- 选择后立即：更新 `settings.language`、重算 `App.lang`、触发一次持久化保存，与主题
  的「即改即存」流程一致。
- 保存失败时保留当前显示语言并显示错误横幅；连续切换时按最新选择重试（与主题逻辑
  相同）。
- `Message::SaveSettings` 保存时排除 `ui_language`（与 `ui_theme` 相同的处理）。

### 4.2 App 状态与辅助方法

- `SettingsState` 增加 `language: LanguagePref`，参与 `from_map` / `to_map` 往返。
- `App` 增加 `lang: Lang`：`new()` 时用默认偏好解析；`apply_loaded()` 解析设置后更新；
  切换语言时立即更新。设置解析失败回退默认设置时同样更新。
- `App` 增加 `tr` / `tr_args` / `tr_plural` 便捷方法，视图层统一 `app.tr("...")`。
- `SettingsState::from_map` 先解析语言偏好，再用该语言生成本次解析其余字段的错误文案。
- `parse_bool` 等内部错误改为本地化文案（带 key 参数）。

### 4.3 视图与组件

- 所有视图（library / game_detail / runners / logs / settings）、`widgets`（layout /
  modal / badges / controls / cover）、`app/view.rs` 的字面量改为 `app.tr(...)`。
- 拿不到 `App` 的纯函数显式增加 `lang: Lang` 参数，不使用全局可变语言状态：
  - `widgets/choices.rs` 的 `arch_choices` / `backend_choices` / `gamescope_choices` /
    `override_mode_choices` / `monitor_choices` 等；
  - `widgets/mod.rs` 中「未选择」「从未」等标签函数；
  - `dialogs::pick(intent, lang)` 的过滤器名称与失败提示；
  - `draft::DraftError::render(lang)`。
- `App::launch_state_label` 通过 `self.lang` 返回本地化文本。
- 布局宽度已自适应，英文文案长度变化不需要改布局；极端长文案继续走现有截断逻辑。

### 4.4 错误提示

- `ErrorNotice` 增加 `kind: NoticeKind`（`General` / `Form` / `ThemeSave` / `LanguageSave`），
  用 `ErrorNotice::form(...)`、`ErrorNotice::theme_save(...)`、`ErrorNotice::language_save(...)`
  构造对应提示；删除现在依赖中文字符串匹配的 `is_form_notice` 与主题错误的 `title` 比较，
  改为判断 `kind`。
- `AppError` 通过 `i18n/errors.rs::app_error(lang, &error) -> String` 渲染：
  - 普通变体输出翻译后的模板（路径、数量、尺寸等作为占位符）；
  - `Storage` / `Prefix` / `Runner` / `Launch` / `Join` 等透传变体输出
    「分类标签：底层原文」，底层原文保持原语言，便于排查。
- 在 `AppError` 转成 `String` 的消息通道边界处传入当前 `lang`。已显示的横幅不会因随后
  切换语言而重绘（横幅是瞬态的，可接受）。

### 4.5 表单校验错误

`draft.rs` 的 `DraftError` 改为结构化：

```rust
pub struct DraftError {
    pub field: DraftField,      // Name / Executable / WorkingDir / Prefix / Resolution /
                                // RefreshRate / Env / DllOverride
    pub kind: DraftErrorKind,   // 每种校验失败一个变体，携带必要数据（如重复的 key）
}

impl DraftError {
    pub fn render(&self, lang: Lang) -> String; // "字段：消息"
}
```

移除 `Display` / `std::error::Error` 实现，避免任何路径绕过本地化。现有测试只断言
`is_err()`，不受影响。

## 5. 语言目录格式

扁平 JSON 对象，key 为点分字符串，value 为文案；UTF-8；key 按字母序排列，便于 diff。

```json
{
  "common.save": "保存",
  "library.subtitle.one": "{games} 个游戏 · {running} 个正在运行",
  "library.subtitle.other": "{games} 个游戏 · {running} 个正在运行"
}
```

`en-US.json` 对应：

```json
{
  "common.save": "Save",
  "library.subtitle.one": "{games} game · {running} running",
  "library.subtitle.other": "{games} games · {running} running"
}
```

规则：

- 两个文件的 key 集合必须完全一致，值不得为空串。
- 同一 key 在两种语言中的 `{placeholder}` 集合必须一致。
- 中文目录即现有文案的搬迁，保持措辞不变（除为占位符/复数做的必要拆分）。

## 6. 新增语言的流程

1. 复制 `locales/en-US.json` 为 `locales/<code>.json`，翻译 value，保持 key 不变。
2. 在 `i18n/mod.rs` 增加一个 `Language` 常量，并加入 `LANGUAGES`。
3. 若主语言 tag 需要特殊映射（如 `ja` → `ja-JP`），在 `language_from_tag` 增加一条
   映射；否则自动按前缀匹配 code。
4. `cargo test -p ui` 通过（key/占位符/源码 key 扫描）。
5. 手动切换检查：两套主题下的换行、按钮宽度、下拉菜单与错误横幅。

该流程写入 `docs/i18n.md`。

## 7. 测试

| 测试 | 内容 |
| --- | --- |
| `catalogues_share_keys` | zh-CN 与 en-US key 集合一致、无空值 |
| `placeholders_are_consistent` | 同一 key 在各语言中的 `{name}` 集合一致 |
| `source_keys_exist` | 扫描 `src/**/*.rs` 中 `tr(`、`.tr(`、`tr_args(`、`.tr_args(`、`tr_plural(`、`tr_plural_args(` 调用，取首个（复数接口取前两个）字符串字面量，断言全部存在于目录 |
| `language_tag_parsing` | `zh_CN.UTF-8` → zh-CN，`en_US.UTF-8` → en-US，`C` → 无匹配，`LANGUAGE=a:b` 取首个可识别项 |
| `language_pref_fallback` | 缺失/未知设置值 → `Auto`；合法 code → `Fixed` |
| `settings_round_trip` | 语言偏好随设置保存/读取往返不丢失 |
| 现有标签测试 | 测试辅助函数固定 `lang`（如 `Fixed(&ZH_CN)`），断言保持确定性 |

手工验收：中文与英文各走一遍游戏库、详情、Runner、设置、日志、删除确认，检查浅色/
深色主题下无空白文字、无截断异常；切换语言后界面立即整体刷新。

## 8. 兼容性与风险

- 已存在用户没有 `ui_language` 设置：解析为 `Auto`；当前测试机 `LANG=en_US.UTF-8`，
  首次升级会显示英文，这是预期行为。
- 以后删除某语言：库中残留的 code 解析为 `Auto`，不会崩溃。
- 英文文案普遍更长：页面头部、按钮、卡片副标题需人工确认不溢出；现有 `middle_truncate`
  与 `Wrapping` 机制继续生效。
- 字体继续使用 `Noto Sans CJK SC`，已覆盖拉丁字符；本规格不新增字体资源。
- 占位符值（路径、错误原文、数字）原样插入，不做转义。
